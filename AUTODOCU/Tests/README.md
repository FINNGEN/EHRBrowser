# AUTODOCU / Tests

Generated Playwright tests that capture the annotated screenshots the
documentation pages in `AUTODOCU/Documentation/` embed. The tests are produced
by the `autodocu` skill from the specs in `AUTODOCU/Outline/`.

## Layout

This folder holds only three kinds of thing:

```
Tests/
  README.md                         # this file
  run_test.sh                        # run ALL sections' tests + diff screenshots + report (generic)
  compare_report.mjs                 # pixel-diff the screenshots + write test_report.md (generic, Node)
  app_control.sh                     # how to start/stop the app (app-specific; generated by build)
  test_report.md                     # generated by run_test.sh: per-section + per-screenshot PASS/FAIL
  playwright/                        # the self-contained Playwright workspace (all infra lives here)
  <n.section_slug>/                  # one folder per documentation section...
    <slug>.spec.ts                   #   ...containing that section's generated test
```

- **`<n.section_slug>/`** — one folder per section, named identically to the
  matching `Outline/` and `Documentation/` folder. Each holds a single
  generated `.spec.ts` that mirrors the section's Outline steps.
- **`playwright/`** — everything Playwright-related, kept out of the way so the
  Tests folder stays readable (see below).
- **`run_test.sh`** / **`app_control.sh`** — the one-command test runner (see
  "Running all tests" below).

## The `playwright/` workspace

`playwright/` is a **self-contained npm project**, deliberately isolated from
the main application — installing Playwright here never adds anything to the
app's root `package.json` / `package-lock.json`, and all of Playwright's
scratch stays inside this folder.

Committed sources:

| File | Meaning |
|------|---------|
| `playwright/package.json` | The isolated npm project. Only dependency: `@playwright/test`. Its `test` script sets `NODE_PATH` so the specs one level up can resolve `@playwright/test`. |
| `playwright/package-lock.json` | Locked dependency versions. |
| `playwright/playwright.config.ts` | Runner config. `baseURL` + `viewport` come from `Outline/README.md`'s `# Run`. `testDir` is `..` (the Tests folder), so it finds `<section>/*.spec.ts`. |
| `playwright/_helpers.ts` | Shared helpers: `highlight` (red box), `clearHighlights`, `shot` (writes a screenshot into `../../Documentation/<section>/screenshots/`). |
| `playwright/.gitignore` | Ignores everything installed/generated below. |

Ignored (installed / regenerated — never committed):

| Path | Meaning |
|------|---------|
| `playwright/node_modules/` | Installed dependencies. Recreate with `npm install`. |
| `playwright/.pw-artifacts/` | Playwright's `outputDir` scratch (e.g. `.last-run.json`). |
| `playwright/.playwright-cli/` | Dumps from the interactive `playwright-cli` selector tool. |
| `playwright/.playwright/`, `test-results/`, `playwright-report/` | Other Playwright scratch/report output. |

## Running all tests

`run_test.sh` runs **every** section's spec in one shot — it starts the app,
waits for it, runs all the specs, diffs the screenshots, stops the app, and
writes a report:

```bash
./AUTODOCU/Tests/run_test.sh            # all sections
./AUTODOCU/Tests/run_test.sh 1.some_sec # optional: pass a filter through to Playwright
```

It works from any directory and always tears the app down, even on failure.

**Screenshots are not overwritten blindly.** Fresh captures go to a temp folder
first (the specs honour `AUTODOCU_SHOT_ROOT`). Each one is then pixel-compared
against the committed image in `Documentation/<section>/screenshots/`. A pixel
only counts as *changed* if a colour channel differs by more than ±16/255 — that
ignores the invisible sub-pixel wobble anti-aliased regions (gradients, filled
charts) show between runs, which can otherwise light up ~9% of a big chart while
looking identical. Then:

- changed pixels **> 1%** → the committed image is **replaced** with the new
  one, and that screenshot is marked **FAIL** (a real, visible change).
- changed pixels **≤ 1%** → the committed image is **kept** (sub-threshold
  rendering noise like anti-aliasing), marked **PASS** — so re-runs don't churn
  the repo with visually-identical images.

The result is `test_report.md` (in this folder): one **bold** row per section
carrying the Playwright pass/fail, one plain row per screenshot carrying its
diff pass/fail, and a final **Total** row (e.g. `2/5`). Exit code is 0 only if
every row passed.

The pieces:

- **`run_test.sh`** is **generic** — identical for every app, shipped by the
  autodocu skill and copied on `init`. It sources `app_control.sh` and never
  hardcodes anything app-specific.
- **`compare_report.mjs`** is **generic** too — a plain Node script (stdlib
  `fs` + `zlib`, no extra dependencies, no Python) that does the PNG pixel-diff
  and writes `test_report.md`.
- **`app_control.sh`** is **app-specific** — it defines `APP_URL` and the
  `start_app` / `stop_app` functions. `build` generates it from the Outline
  `# Run` section, so edit the Outline and re-run `build` to refresh it (or
  tweak the commands by hand).

## Running the tests manually

```bash
cd AUTODOCU/Tests/playwright
npm install                       # first time only — creates node_modules/ here
npm run install-browsers          # first time only — downloads chromium
# (start the app first, per Outline/README.md '# Run')
npm test                          # all sections
npm test -- 1.some_section        # a single section
```

`npm test` sets `NODE_PATH` for you. If you invoke `npx playwright test`
directly instead, prefix it: `NODE_PATH="$PWD/node_modules" npx playwright test`
— the specs live one level up, so Node needs to be told where this folder's
`node_modules` is.
