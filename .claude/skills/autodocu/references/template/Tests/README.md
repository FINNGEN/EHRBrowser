# AUTODOCU / Tests

Generated Playwright tests that capture the annotated screenshots the
documentation pages in `AUTODOCU/Documentation/` embed. The tests are produced
by the `autodocu` skill from the specs in `AUTODOCU/Outline/`.

## Layout

The Tests folder stays readable: per-section spec folders, the one-command
runner and its `.env`, the generated report, and a single `Scripts/` folder
that holds all the machinery the runner drives.

```
Tests/
  README.md                          # this file
  run_test.sh                        # run ALL sections' tests + diff screenshots + report (generic)
  .env                               # tunable harness settings (diff threshold, ...) sourced by run_test.sh
  test_report.md                     # generated by run_test.sh: per-section + per-screenshot PASS/FAIL + visual diffs
  test_report/                       # generated: BEFORE/AFTER PNGs for changed screenshots (embedded in test_report.md)
  Scripts/                           # the machinery run_test.sh drives (kept out of the way)
    compare_report.mjs               #   pixel-diff the screenshots + write test_report.md (generic, Node)
    app_control.sh                   #   how to start/stop the app (app-specific; generated by build)
    playwright/                      #   the self-contained Playwright workspace (all infra lives here)
  <n.section_slug>/                  # one folder per documentation section...
    <slug>.spec.ts                   #   ...containing that section's generated test
```

- **`<n.section_slug>/`** — one folder per section, named identically to the
  matching `Outline/` and `Documentation/` folder. Each holds a single
  generated `.spec.ts` that mirrors the section's Outline steps. It imports the
  helpers from `../Scripts/playwright/_helpers`.
- **`Scripts/`** — everything the runner drives (the Playwright workspace, the
  app start/stop controls, and the diff/report script), kept out of the way so
  the Tests folder stays readable (see below).
- **`run_test.sh`** / **`.env`** — the one-command test runner and its settings
  (see "Running all tests" below).

## The `Scripts/playwright/` workspace

`Scripts/playwright/` is a **self-contained npm project**, deliberately isolated
from the main application — installing Playwright here never adds anything to the
app's root `package.json` / `package-lock.json`, and all of Playwright's
scratch stays inside this folder.

Committed sources:

| File | Meaning |
|------|---------|
| `Scripts/playwright/package.json` | The isolated npm project. Only dependency: `@playwright/test`. Its `test` script sets `NODE_PATH` so the specs two levels up can resolve `@playwright/test`. |
| `Scripts/playwright/package-lock.json` | Locked dependency versions. |
| `Scripts/playwright/playwright.config.ts` | Runner config. `baseURL` + `viewport` come from `Outline/README.md`'s `# Run`. `testDir` is `../..` (the Tests folder), so it finds `<section>/*.spec.ts`. |
| `Scripts/playwright/_helpers.ts` | Shared helpers: `highlight` (red box), `clearHighlights`, `shot` (writes a screenshot into `../../../Documentation/<section>/screenshots/`, unless `AUTODOCU_SHOT_ROOT` redirects it). |
| `Scripts/playwright/.gitignore` | Ignores everything installed/generated below. |

Ignored (installed / regenerated — never committed):

| Path | Meaning |
|------|---------|
| `Scripts/playwright/node_modules/` | Installed dependencies. Recreate with `npm install`. |
| `Scripts/playwright/.pw-artifacts/` | Playwright's `outputDir` scratch (e.g. `.last-run.json`). |
| `Scripts/playwright/.playwright-cli/` | Dumps from the interactive `playwright-cli` selector tool. |
| `Scripts/playwright/.playwright/`, `test-results/`, `playwright-report/` | Other Playwright scratch/report output. |

## Running all tests

`run_test.sh` runs **every** section's spec in one shot — it starts the app,
waits for it, runs all the specs, diffs the screenshots, stops the app, and
writes a report:

```bash
./AUTODOCU/Tests/run_test.sh                  # all sections (changed screenshots -> review)
./AUTODOCU/Tests/run_test.sh 1.some_sec       # optional: pass a filter through to Playwright
./AUTODOCU/Tests/run_test.sh --accept-changes # adopt changed screenshots as the new baseline
```

It works from any directory and always tears the app down, even on failure.
The flag and a filter can be combined (`--accept-changes 1.some_sec`).

**Settings live in `.env`** (next to `run_test.sh`). `run_test.sh` sources it on
start; the only knob today is `AUTODOCU_DIFF_THRESHOLD` (the changed-pixel %
below). `AUTODOCU_SHOT_ROOT` and `PLAYWRIGHT_JSON_OUTPUT_NAME` are set by the
runner itself per run and are documented there for reference.

**Screenshots are not overwritten blindly.** Fresh captures go to a temp folder
first (the specs honour `AUTODOCU_SHOT_ROOT`). Each one is then pixel-compared
against the committed image in `Documentation/<section>/screenshots/`. A pixel
only counts as *changed* if a colour channel differs by more than ±16/255 — that
ignores the invisible sub-pixel wobble anti-aliased regions (gradients, filled
charts) show between runs, which can otherwise light up ~9% of a big chart while
looking identical. Then:

- changed pixels **> threshold** → a real, visible change, marked **FAIL**. By
  **default** the committed image is **kept** (never silently overwritten) and the
  old and new images are saved as a BEFORE/AFTER pair under `test_report/` so you
  can eyeball the difference. Re-run with **`--accept-changes`** to instead
  **replace** the committed image with the new capture (marked PASS) — that blesses
  the new screenshots as the baseline for future runs.
- changed pixels **≤ threshold** → the committed image is **kept** (sub-threshold
  rendering noise like anti-aliasing), marked **PASS** — so re-runs don't churn
  the repo with visually-identical images.

The result is `test_report.md` (in this folder): one **bold** row per section
carrying the Playwright pass/fail, one plain row per screenshot carrying its
diff pass/fail, and a final **Total** row (e.g. `2/5`). Exit code is 0 only if
every row passed. When screenshots changed (and were not accepted), the report
also gets a **Visual changes to review** section — grouped by section, then by
screenshot — showing the BEFORE and AFTER images side by side (backed by the PNGs
in `test_report/`), so a diff is easy to review in the rendered Markdown.

The pieces:

- **`run_test.sh`** is **generic** — identical for every app, shipped by the
  autodocu skill and copied on `init`. It sources `.env` and
  `Scripts/app_control.sh` and never hardcodes anything app-specific.
- **`Scripts/compare_report.mjs`** is **generic** too — a plain Node script
  (stdlib `fs` + `zlib`, no extra dependencies, no Python) that does the PNG
  pixel-diff and writes `test_report.md`.
- **`Scripts/app_control.sh`** is **app-specific** — it defines `APP_URL` and the
  `start_app` / `stop_app` functions. `build` generates it from the Outline
  `# Run` section, so edit the Outline and re-run `build` to refresh it (or
  tweak the commands by hand).

## Running the tests manually

```bash
cd AUTODOCU/Tests/Scripts/playwright
npm install                       # first time only — creates node_modules/ here
npm run install-browsers          # first time only — downloads chromium
# (start the app first, per Outline/README.md '# Run')
npm test                          # all sections
npm test -- 1.some_section        # a single section
```

`npm test` sets `NODE_PATH` for you. If you invoke `npx playwright test`
directly instead, prefix it: `NODE_PATH="$PWD/node_modules" npx playwright test`
— the specs live two levels up, so Node needs to be told where this folder's
`node_modules` is.
